Requirement-centred, not one record at a time. The specification calls for a CMMC workspace with its assessment objectives visible together, and that matches how you run a gap analysis — you walk 3.1.1[a] through [f] with the client in one sitting. Every objective on this screen carries its own determination; the requirement's status is derived and never edited. Guidance sits on the objective that needs it. Evidence type and example come from your own worksheet; the assessment consideration is the question to ask. Both are marked as RainTech practitioner content — not NIST, not DoD, so a report never cites them as authority. Official scoring is not shown, deliberately. The DoD Assessment Methodology point values are not ingested, and the specification forbids inventing a generic readiness score. Counts are shown; a score is not. Keyboard: j / k move between requirements. The rail shows determined-objectives over total, so you can see where you stopped.
